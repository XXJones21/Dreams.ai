# Visual Generation

Images and video are generated by a **local ComfyUI** (`127.0.0.1:8188`), driven through the shared **`engram_comfy`** harness. Dreams.ai never runs diffusers in-process for the pipeline path; it submits ComfyUI workflow graphs and polls for results.

## The harness

`engram_comfy` is `pip install -e`'d (declared in `Backend/Python/requirements.txt`) and resolves to `…/Engram/Resources/engram_comfy`. It exposes:

- `ComfyImageGenerator(default_workflow=…).generate_image(prompt, workflow=…)` → `{filename, filepath, metadata: {workflow, prompt_id, seed, asset_url, generated_at}}`
- `ComfyVideoGenerator(default_workflow=…).generate_video(prompt, image_input=…, workflow=…)` → parallel shape

`COMFY_TRANSPORT=direct` (set by `api_server.py` / `test_gui.py` at import) makes the harness talk straight to ComfyUI on `:8188`. The alternative is `COMFY_TRANSPORT=rust` + `COMFY_BASE_URL=http://127.0.0.1:8765` to go through Valinor's Rust supervisor.

## Workflows

Workflow JSONs live in the `engram_comfy` package (`…/engram_comfy/workflows/`):

| Workflow | File | Loader / key node | Model |
| --- | --- | --- | --- |
| Image (default) | `scene_image_sdxl_turbo.json` | `CheckpointLoaderSimple` | `sd_xl_turbo_1.0_fp16.safetensors` |
| Image (LoRA) | `scene_image_sdxl_lora.json` | + LoRA loader | SDXL base + LoRA |
| Video (default) | `scene_video_ltx.json` | `LTXVCheckpointLoader` (custom node) | LTX-Video |
| Video (cinematic) | `scene_video_wan22.json` | Wan2.2 nodes | Wan2.2 |
| (aux) | `skybox_sdxl_turbo.json` | — | SDXL-Turbo |

The agent picks the image workflow by name (`scene_image_sdxl_turbo`) and the video workflow by flag: `scene_video_wan22` if `video_cinematic` else `scene_video_ltx` (`agents.py:680`).

## Models on disk

Models live in `Backend/Python/models/` (HF diffusers caches + single-file GGUF/safetensors), exposed to ComfyUI via `extra_model_paths.yaml`. The verified-working ComfyUI install is `D:\Tools\ComfyUI_windows_portable_nvidia\ComfyUI_windows_portable`. See [`CLAUDE.md`](../../CLAUDE.md) → "Local inference setup" for the full model inventory, the torch-CUDA fix, and the Flux benchmark.

## What is actually proven to work

- **Flux.1-dev Q4_K_S GGUF** image generation is verified end-to-end on the RTX 4080 (via `UnetLoaderGGUF` + clip_l + t5xxl + 16-channel Flux VAE). This is the path the prior session validated.
- **SDXL-Turbo** (the *current pipeline default*) is **not currently runnable** on the live ComfyUI: its checkpoint list is empty, so the `sd_xl_turbo_1.0_fp16.safetensors` reference fails validation (`value_not_in_list`). The Flux work used a GGUF UNet loader, not `CheckpointLoaderSimple`, so the SDXL-Turbo `.safetensors` was never registered. See [operations/status-and-roadmap.md](../operations/status-and-roadmap.md).

## Performance notes

- SDXL-Turbo (when present) is 1-step, ~13 s. Flux Q4 GGUF: cold ~64 s, warm-same-prompt ~16 s, **warm-new-prompt ~51 s**. The Flux bottleneck is the T5 text encoder (9.2 GB fp16, evicted between runs), not the UNET — the top optimization is `t5xxl_fp16` → `t5xxl_fp8_e4m3fn` or a T5 GGUF.

## Roadmap

Image upgrade SDXL-Turbo → **Flux.1 Krea Dev** is the highest-value aesthetic lever; video → **Wan 2.6 Reference-to-Video** for style-cloning. Full detail in [`CLAUDE.md`](../../CLAUDE.md) → "Model upgrade direction" and [operations/status-and-roadmap.md](../operations/status-and-roadmap.md).
